# Search point of sale

This endpoint allows to search the points of sale associated with the Access Token user, using various filters and pagination information. In case of success, the request will return a response with status 200.

**GET** `/v2/pos`

## Request parameters

### Query

- `external_id` (string, optional)
  Filters results by the external identifier of the point of sale, defined by the integrator system at the time of its creation.

- `store_id` (string, optional)
  Filters results by the identifier of the store to which the points of sale belong. Cannot be used together with `external_store_id` in the same request.

- `external_store_id` (string, optional)
  Filters results by the external identifier of the store, defined by the integrator system. Cannot be used together with `store_id` in the same request.

- `category` (integer, optional)
  Filters results by the MCC category code assigned to the point of sale. Must be a valid `integer`.

- `offset` (integer, optional)
  Number of results to skip from the beginning of the result set for pagination. Must be a non-negative `integer`. When not specified, defaults to 0.

- `limit` (integer, optional)
  Maximum number of results to return. Must be an `integer` between 1 and 30 inclusive. When not specified, defaults to 30.

## Response parameters

- `paging` (object, optional)
  It contains the pagination information for the search results.

  - `paging.total` (integer, optional)
  It is the total number of points of sale found matching the applied filters.

  - `paging.offset` (integer, optional)
  It is the number of elements skipped from the beginning of the result set.

  - `paging.limit` (integer, optional)
  It is the maximum number of points of sale returned in this response.

- `data` (array, optional)
  It contains the list of points of sale found based on the applied filters.

  - `data[].id` (integer, optional)
  It is the unique numeric identifier of the point of sale, automatically generated by Mercado Pago at creation time. When you register a point of sale, you will receive a corresponding ID. This ID can be used for various operations, including retrieving, updating, or deleting the point of sale.

  - `data[].name` (string, optional)
  It is the name of the point of sale, defined by the integrator at creation time.

  - `data[].status` (string, optional)
  It indicates the current status of the point of sale. Possible values: `active` (the point of sale is enabled and available to receive payments) and `inactive` (the point of sale is disabled and cannot receive payments).
Possible enum values:

  - `active`

  - `inactive`

  - `data[].date_created` (string, optional)
  Date and time the point of sale was created in ISO 8601 format. For example, 2024-08-08T19:29:45.019Z.

  - `data[].date_last_updated` (string, optional)
  Date and time of the last update to the point of sale data in ISO 8601 format. For example, 2024-08-08T19:29:45.019Z.

  - `data[].user_id` (integer, optional)
  The `user_id` corresponds to the `collector_id`. It refers to the identifier of the Mercado Pago account that receives the money from sales, that is, the account responsible for collecting the funds.

  - `data[].external_id` (string, optional)
  It is the external identifier of the point of sale, defined by the integrator system at creation time.

  - `data[].qr_response` (object, optional)
  QR code data automatically generated and associated with the point of sale at creation time.

  - `data[].qr_response.uuid` (string, optional)
  It is the unique identifier of the QR code associated with this point of sale, represented as a 64-character hexadecimal `string` (SHA-256 hash).

  - `data[].qr_response.image` (string, optional)
  It is the URL of the QR code image to be printed or displayed for receiving payments.

  - `data[].qr_response.template_document` (string, optional)
  It is the URL of the PDF template document containing the QR code, ready for printing.

  - `data[].qr_response.template_image` (string, optional)
  It is the URL of the image template containing the QR code, ready for printing.

  - `data[].qr_response.qr_code` (string, optional)
  It is the raw QR code `string` that can be encoded into a QR image by the integrator system.

  - `data[].config` (object, optional)
  Point of sale configuration returned by the API.

  - `data[].config.qr` (object, optional)
  QR code configuration for the point of sale.

  - `data[].config.qr.operating_mode` (string, optional)
  Operating mode configured for the point of sale. Possible values: `pdv`, `unattended`, `self_service`, `standalone`.
Possible enum values:

  - `pdv`

  - `unattended`

  - `self_service`

  - `standalone`

  - `data[].config.qr.category` (integer, optional)
  MCC category code assigned to the point of sale, when applicable.

## Errors

| Status | Error | Description |
| ------- | ------- | ----------- |
| 400 | conflicting_store_filters | The `store_id` and `external_store_id` filters cannot be sent simultaneously in the same request. Use only one of them. |
| 400 | invalid_query_param | One or more query parameters contain an invalid value. Verify that category is a valid `integer`, offset is a non-negative `integer`, and limit is an `integer` between 1 and 30. |
| 400 | invalid_store_id | The `store_id` filter value is not a valid `number`. Verify that the value sent is a valid `integer`. |
| 401 | unauthorized | The value sent as Access Token is incorrect or missing. Please check and try again with a valid Access Token. |
| 500 | internal_server_error | An unexpected error occurred on the server. This is a transient failure not related to the request data. Please try again after a few moments. |

## Request example

### cURL

```bash
curl -X GET \
  'https://api.mercadopago.com/v2/pos?external_id=<EXTERNAL_ID>&store_id=<STORE_ID>&external_store_id=<EXTERNAL_STORE_ID>&category=<CATEGORY>&offset=<OFFSET>&limit=<LIMIT>' \
  -H 'Content-Type: application/json' \
  -H 'Authorization: Bearer <ACCESS_TOKEN>'
```
